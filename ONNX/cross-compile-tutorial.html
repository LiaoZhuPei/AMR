理解交叉编译的全局流程

动手前先建立清晰的心智模型：每一步在做什么、产出是什么、如何验证

// 什么是交叉编译

普通编译是"在A机器上编译，产物也在A上跑"。交叉编译是"在A机器上编译，但产物要在B机器上跑"。A是你的x86 Win/WSL2，B是飞腾AArch64。

[ 宿主机 Host ] [ 目标机 Target ] x86_64 WSL2 Ubuntu AArch64 飞腾/麒麟 源代码 (.cpp / .c) │ ▼ aarch64-linux-gnu-g++ ──────────► 可执行文件 (ELF AArch64) （交叉编译器） 直接在飞腾上运行 │ │ 同时需要 ▼ AArch64版 ONNX Runtime libonnxruntime.so (arm64) ──────────► 一起拷贝到目标机
// 本实验的目标

我们会编译一个最简C++推理程序，它做一件事：

实验模型说明

输入：4个float（模拟4维特征向量）
模型：单层全连接 Linear(4→2)，用Python生成并导出为ONNX
输出：2个float（模拟二分类得分）
C++程序：加载此ONNX，跑一次推理，打印结果

02

生成实验用 ONNX 模型

用Python生成一个最简单的全连接模型，导出ONNX，并在本机验证推理结果

为什么用Python生成模型

ONNX文件本身与平台无关。在x86 Win/WSL2上生成的 .onnx 文件，直接拷到飞腾上就能用，不需要在AArch64上重新生成。

// 2.1 在 WSL2 里安装 Python 依赖
WSL2 bash
pip3 install torch onnx onnxruntime numpy \
    -i https://pypi.tuna.tsinghua.edu.cn/simple
// 2.2 生成模型并导出 ONNX
WSL2 bash — 创建 gen_model.py
cat > ~/cross-lab/gen_model.py <<'EOF'
import torch, torch.nn as nn, numpy as np

# ── 定义最简模型：Linear(4→2) ──
class TinyModel(nn.Module):
    def __init__(self):
        super().__init__()
        # 固定权重，方便后续验证C++结果是否一致
        self.fc = nn.Linear(4, 2, bias=True)
        nn.init.constant_(self.fc.weight, 0.5)
        nn.init.constant_(self.fc.bias, 0.1)

    def forward(self, x):
        return self.fc(x)

model = TinyModel().eval()

# ── 固定输入，用于验证 ──
dummy = torch.tensor([[1.0, 2.0, 3.0, 4.0]])

# ── Python本机推理结果（作为基准）──
with torch.no_grad():
    out = model(dummy)
print(f"[Python基准] 输入: {dummy.numpy()}")
print(f"[Python基准] 输出: {out.numpy()}")
# 预期: weight=0.5, bias=0.1
# out[0] = 1*0.5+2*0.5+3*0.5+4*0.5+0.1 = 5.1+0.1 = 5.1（两个神经元相同）

# ── 导出 ONNX ──
torch.onnx.export(
    model, dummy,
    "tiny_model.onnx",
    export_params=True,
    opset_version=11,
    input_names=['input'],
    output_names=['output'],
)
print("\n✓ 导出: tiny_model.onnx")

# ── 用 ONNX Runtime 在本机再验证一次 ──
import onnxruntime as ort
sess = ort.InferenceSession("tiny_model.onnx")
inp = np.array([[1.0, 2.0, 3.0, 4.0]], dtype=np.float32)
res = sess.run(None, {'input': inp})
print(f"[ONNX本机] 输出: {res[0]}")
print("✓ Python/ONNX结果一致，记下这个数值，最后和C++结果对比！")
EOF

python3 ~/cross-lab/gen_model.py
✓ 期望输出（记下这个数值！）

[Python基准] 输出: [[5.1 5.1]]
[ONNX本机] 输出: [[5.1 5.1]]

这是你的基准值。最后C++程序在AArch64上的输出必须和这个一致，否则说明哪里出了问题。

03

获取 AArch64 版 ONNX Runtime

这是交叉编译里最关键的一步：链接的 .so 库必须是 AArch64 架构，否则目标机上无法运行

💡 为什么不能用系统里已有的 ONNX Runtime

你的 WSL2 是 x86_64，pip install 装的 onnxruntime 也是 x86_64 版本的 .so 文件。把这个 .so 拷到 AArch64 机器上，完全无法加载（ELF格式不兼容）。必须单独获取 AArch64 版本。

WSL2 bash

# 解压
tar -xzf onnxruntime-linux-aarch64-1.17.3.tgz

# 重命名方便引用
mv onnxruntime-linux-aarch64-1.17.3 onnxruntime-arm64/

# 查看目录结构
ls onnxruntime-arm64/
# 期望：include/  lib/

ls onnxruntime-arm64/lib/
# 期望：libonnxruntime.so  libonnxruntime.so.1.17.3 等
// 验证：确认 .so 文件确实是 AArch64

编写 C++ 推理代码

编写调用 ONNX Runtime C++ API 的推理程序，注释说明每一行的作用

📌 头文件是平台无关的，只有 .so 是平台相关的

你在这里写的 #include "onnxruntime_cxx_api.h"，这个头文件在x86和arm64上内容完全一样。平台差异只体现在链接时用哪个 .so 文件。

// 创建 infer.cpp
WSL2 bash — 创建 infer.cpp
cat > ~/cross-lab/infer.cpp <<'EOF'
#include <iostream>
#include <vector>
#include <string>
#include "onnxruntime_cxx_api.h"   // ONNX Runtime C++ API

int main(int argc, char* argv[]) {

    // ── 1. 确定模型路径（从命令行参数或默认值）──
    std::string model_path = (argc > 1) ? argv[1] : "tiny_model.onnx";
    std::cout << "加载模型: " << model_path << "\n";

    // ── 2. 初始化 ONNX Runtime 环境 ──
    // ORT_LOGGING_LEVEL_WARNING: 只显示警告以上的日志
    Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "InferTest");

    // ── 3. 配置 Session 选项 ──
    Ort::SessionOptions session_options;
    session_options.SetIntraOpNumThreads(1);   // 单线程，便于实验
    session_options.SetGraphOptimizationLevel(
        GraphOptimizationLevel::ORT_ENABLE_BASIC
    );

    // ── 4. 加载模型，创建推理 Session ──
    Ort::Session session(env, model_path.c_str(), session_options);
    std::cout << "模型加载成功\n";

    // ── 5. 获取输入输出信息 ──
    Ort::AllocatorWithDefaultOptions allocator;

    // 输入节点名称（对应 Python 导出时的 input_names=['input']）
    auto input_name_ptr = session.GetInputNameAllocated(0, allocator);
    std::string input_name(input_name_ptr.get());

    // 输出节点名称
    auto output_name_ptr = session.GetOutputNameAllocated(0, allocator);
    std::string output_name(output_name_ptr.get());

    std::cout << "输入名: " << input_name
              << " | 输出名: " << output_name << "\n";

    // ── 6. 准备输入数据 ──
    // 和 Python 验证时一样的输入：[1.0, 2.0, 3.0, 4.0]
    std::vector<float> input_data = {1.0f, 2.0f, 3.0f, 4.0f};

    // 输入张量的形状：batch_size=1, features=4
    std::vector<int64_t> input_shape = {1, 4};

    // ── 7. 创建输入 Tensor ──
    // Tensor 是 ONNX Runtime 的数据容器
    auto memory_info = Ort::MemoryInfo::CreateCpu(
        OrtAllocatorType::OrtArenaAllocator,
        OrtMemType::OrtMemTypeDefault
    );

    Ort::Value input_tensor = Ort::Value::CreateTensor<float>(
        memory_info,
        input_data.data(),      // 数据指针
        input_data.size(),      // 元素个数
        input_shape.data(),     // 形状数组
        input_shape.size()      // 形状维度数
    );

    // ── 8. 执行推理 ──
    const char* input_names[]  = {input_name.c_str()};
    const char* output_names[] = {output_name.c_str()};

    auto output_tensors = session.Run(
        Ort::RunOptions{nullptr},
        input_names,    1,      // 输入名称数组，数量
        &input_tensor,  1,      // 输入Tensor数组，数量
        output_names,   1       // 输出名称数组，数量
    );

    // ── 9. 获取输出结果 ──
    float* output_data = output_tensors[0].GetTensorMutableData<float>();
    auto output_shape  = output_tensors[0].GetTensorTypeAndShapeInfo().GetShape();

    std::cout << "\n=== 推理结果 ===\n";
    std::cout << "输入:  [1.0, 2.0, 3.0, 4.0]\n";
    std::cout << "输出:  [";
    for (int64_t i = 0; i < output_shape[1]; ++i) {
        if (i > 0) std::cout << ", ";
        std::cout << output_data[i];
    }
    std::cout << "]\n";
    std::cout << "期望:  [5.1, 5.1]  ← 应与Python结果一致\n";

    return 0;
}
EOF

echo "✓ infer.cpp 创建完成"

交叉编译

用 aarch64-linux-gnu-g++ 把 infer.cpp 编译成 AArch64 可执行文件

WSL2 bash

// 5.2 执行交叉编译

这是整个教程最核心的一条命令，每个参数都有明确含义：

WSL2 bash
cd ~/cross-lab aarch64-linux-gnu-g++ \ infer.cpp \ -o infer_arm64 \ -I ./onnxruntime-arm64/include \ -L ./onnxruntime-arm64/lib \ -lonnxruntime \ -Wl,-rpath,'$ORIGIN/lib' \ -std=c++17 \ -O2 echo "编译完成，返回码: $?"
📖 每个编译参数的含义
参数含义
aarch64-linux-gnu-g++用 AArch64 交叉编译器，不是普通的 g++
infer.cpp源文件
-o infer_arm64输出文件名
-I ./onnxruntime-arm64/include头文件搜索路径（找 .h 文件）
-L ./onnxruntime-arm64/lib库文件搜索路径（找 .so 文件）
-lonnxruntime链接 libonnxruntime.so
-Wl,-rpath,'$ORIGIN/lib'运行时在自身同级 lib/ 目录里找 .so
-std=c++17使用 C++17 标准
-O2开启优化
